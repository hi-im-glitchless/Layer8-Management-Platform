## Objective
Make the Dashboard Current/Next project cards link to the corresponding board card. Today the cards are inert `<div>`s — clicking does nothing. Per the Phase 24 success criteria, they should deep-link to `/board?card=<id>`.

The implementation follows plan 24-02's pattern: do the assignmentId→cardId lookup at click time, not at render time, so we avoid spawning multiple parallel queries when the dashboard mounts.

### Task 2: Thread assignmentId through buildProjectTimeline
Edit `frontend/src/features/dashboard/utils.ts`:
- In `buildProjectTimeline`, when constructing each `DashboardProject` from an underlying Assignment row, populate `assignmentId: assignment.id`.
- For any code path that constructs a synthetic/placeholder `DashboardProject` (e.g. an "empty" state for users with no current assignment), leave `assignmentId` undefined.
- If the function projects from a list-of-Assignments query, just spread `id` into the projection. One-line change.

**Commit:** `feat(24-04): thread Assignment.id into DashboardProject.assignmentId in buildProjectTimeline`

### Task 3: Make ProjectCard navigate to /board?card=<id> on click
Edit `frontend/src/features/dashboard/components/ProjectCard.tsx`:

1. Import `useNavigate` from `react-router-dom` and `useQueryClient` from `@tanstack/react-query`.
2. Import the same `boardApi.listCards` (or `useBoardCardByAssignmentId`'s underlying `queryFn`) as plan 24-02's hook so cache keys align. Cache-key alignment is important: when the user clicks the dashboard card and lands on the board, the same `?card=<id>` lookup elsewhere should hit cache, not refetch.
3. Convert the outer wrapping `<div>` to one of:
   - A `<Link>` from `react-router-dom` with `to={`/board?card=...`}` IF you can compute the cardId synchronously (you can't — we need a roundtrip).
   - A `<button>` (or styled-as-card div with `role="button"`, `tabIndex={0}`, keyboard handlers) whose onClick performs the lookup + navigation.
4. Recommended: use a `<button>` styled as the existing card; on click, `await queryClient.fetchQuery({ queryKey: ['board','cards',{assignmentId}], queryFn: () => boardApi.listCards({assignmentId})} )`; if `cards[0]` exists, `navigate(`/board?card=${cards[0].id}`)`; else no-op (silent — the dashboard card itself remains useful as an info display).
5. When `assignmentId` is undefined, render the existing static `<div>` (no button wrapper, no onClick). Behaviour: the card looks identical to today.
6. Preserve the existing variant prop ("current" | "next") and all visual styling; the link/button wrapper is purely structural.
7. Ensure focus ring + hover state are visible (use the same Tailwind classes as Schedule clickable cells or Board KanbanCards — research the project's existing pattern; do NOT invent a new visual style).
8. **Do NOT** open in a new tab (consistent with plans 24-02 and 24-03).

**Commit:** `feat(24-04): ProjectCard navigates to /board?card=<id> when assignmentId present`
