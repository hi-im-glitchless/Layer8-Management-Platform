<objective>
Board card file uploads must accept single files up to 500MB (currently rejected at 50MB by the multer per-file cap), aligning every layer in the board-file upload path to a single 500MB limit so that only files >500MB are rejected, always with a clear, accurate message. The previously-failing ~200MB upload must succeed.

Root cause (confirmed, high confidence): `MAX_FILE_BYTES = 50 * 1024 * 1024` in boardFileService.ts undercuts the already-500MB `MAX_CARD_BYTES` card quota and the frontend's 500MB assumptions. Secondary: the frontend collapses BOTH board-file 413s into a misleading "Quota exceeded" toast; and both nginx deploy paths clip large bodies before they reach the app (10M in deploy/nginx-layer8.conf; nginx default ~1MB in launcher.sh which has no directive at all).

STRICTLY board files only. Do NOT touch documents.ts, executiveReport.ts, templateAdapter.ts, or profile.ts avatar limits — those are separate features with no 500MB intent and stay at their current values.

500MB = 524288000 bytes = 500 * 1024 * 1024.
</objective>
