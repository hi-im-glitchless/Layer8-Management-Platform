<objective>
Fix the verified bug (09-RESEARCH.md) where deleting the LAST pentester's Assignment
for a project in the Schedule leaves the project's card "hung up" in the Planner with
zero pentesters. Three coordinated changes: (1) backend service guard — after deleting
an assignment, for each non-null linked project count remaining assignments and, only
when that count is EXACTLY 0, move that project's BoardCard to the existing 'stopped'
stage (never delete); (2) frontend hook — useDeleteAssignment invalidates ['board','cards']
so the acting client's Planner refreshes; (3) route — emit board:invalidate so other
connected clients refresh too. The multi-pentester case is protected by the zero-count
boundary (counted over projectId OR splitProjectId); schedule isolation is preserved —
the only DB write is BoardCard.stage, with no Prisma migration.
</objective>
