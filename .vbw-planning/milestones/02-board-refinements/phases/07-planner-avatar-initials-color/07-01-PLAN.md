Change the pentester avatar circles on the PLANNER / BOARD (Kanban) cards ONLY so each circle shows a
two-letter monogram — first initial of the first name + first initial of the last name, uppercase
(single initial for mononyms; graceful fallback for missing names) — on a background colour
DETERMINISTICALLY derived from the account (hash of the stable teamMemberId). The Schedule view stays
visually unchanged.

DECISIONS (made; do not re-litigate):
- PLANNER-ONLY. The entire change lives in frontend/src/features/board/components/KanbanCard.tsx (+ its
  test). The shared shadcn avatar.tsx primitive MUST NOT change. ScheduleGrid.tsx MUST NOT change
  (research confirms it is hand-rolled and decoupled from avatar.tsx — zero schedule regression risk).
- COLOUR SOURCE = deterministic hash of the stable teamMemberId (a cuid), NOT the display name — so a
  rename never changes someone's colour ("tied to the account"). Map to a fixed, curated, white-text-
  readable sub-palette (~12 mid-saturation entries drawn from the schedule COLOR_PALETTE family) defined
  LOCALLY in KanbanCard.tsx. Pale/pastel entries are excluded so white text is always legible. No DB
  column, no admin UI, no migration.
- INITIALS = first token initial + last token initial, uppercased; single-token names -> one initial;
  missing/empty name -> '?' (never crash). User.displayName is a single nullable string (no firstName/
  lastName), so parse by splitting on whitespace.
- DROP THE PHOTO: the board always shows the initials+colour monogram regardless of avatarUrl — no
  <AvatarImage>, no avatarUrl read.
- PRESERVE PHASE-4 BEHAVIOUR: dedupe one circle per pentester by teamMemberId (uniquePentesters), and
  the AvatarGroup cap of 3 + "+N" overflow. Keep the name in the Avatar title for a11y/hover.

NON-NEGOTIABLE schedule isolation: frontend-only, board-only, zero backend work. No schedule-table
writes, no Prisma migration, no change to avatar.tsx / ScheduleGrid.tsx / types.ts / boardService.ts /
constants.ts.
</objective>
