<objective>
Broaden board-file LIST + DOWNLOAD access to any authenticated team member while keeping every
other card action on the existing assigned/ADMIN/PM model. Mechanism (decided): add a lighter
read guard requireCardExists (auth + boardCard.findUnique for 404 + attach req.boardCard, NO
assignment read, no role branch) and use it in place of requireCardAccess on ONLY the two read
routes (GET /cards/:cardId/files and GET /cards/:cardId/files/:fileId/download). Upload, delete,
comments, notes, archive, and notifications keep requireCardAccess. Add a route-level regression
test proving the new policy plus that mutations still 403, cross-card fileId still 404, quarantine
still 410, and the assigned-user happy path is unbroken.
NON-NEGOTIABLE: schedule isolation — neither the new guard nor the file routes may read or write
Assignment/TeamMember/Absence/Holiday. requireCardExists reading only BoardCard is an isolation
improvement over requireCardAccess. Keep the SCHEDULE-ISOLATION INVARIANT JSDoc in boardFiles.ts
intact and add a matching annotation on the new guard. No Prisma migration.
SCOPE DISCIPLINE: relax ONLY the file list + download routes. Do NOT relax board/card visibility
(GET /cards and GET /cards/:id are already requireAuth-only, so a non-assigned user already reaches
the card — reachability is satisfied with no further change). No frontend change is required:
FilesPanel.tsx already renders Download for all files and delete is separately gated.
</objective>
