<objective>
Fix the production bug where planner/board card avatars show a single initial for
real accounts. Root cause (verified in 08-RESEARCH.md): pentesterName() and
pentesterInitials() in KanbanCard.tsx resolve the editable TeamMember alias
(teamMember.displayName) BEFORE the linked account's user.displayName. In production
the alias holds only a first name ("Rui") while user.displayName is the full
"Rui Marques", so the alias shadows the full name and only one initial renders. Flip
the precedence in BOTH helpers so a linked user's full name wins, keeping the alias as
the fallback for backlog members (no linked user). Planner-only; the Schedule keeps its
current alias-first behaviour. No backend, no Prisma migration, no schedule change.
</objective>

cannot by itself express an alias that differs from user.displayName. The new regression
must construct an assignment object inline (or via an extended helper) where the alias
and user.displayName diverge.
