<objective>
Grant the PM role read/open access to archived cards in the planner while keeping
archiving strictly ADMIN-only.

Two coordinated changes, in disjoint files:
1. Frontend: widen the "Show Archived" toggle gate in BoardFilters.tsx from
   hasRole('ADMIN') to hasRole('PM') so PM (and, via the >= hierarchy, ADMIN)
   can reveal the Archived column and open archived cards + their files. All
   backend read endpoints already permit PM (requireAuth only; listCards returns
   all stages), so no backend read change is needed.
2. Backend: close the drag-to-archive hole. The PATCH /cards/:id handler today
   only blocks NORMAL (the stage='archived' check lives inside the `if
   (!isManager)` branch), so a PM could archive-by-dragging a card into the
   Archived column. Move/add an explicit guard so PM (and NORMAL) are rejected
   with 403 when setting stage='archived'; only ADMIN may set it. PM must still
   be able to PATCH cards to non-archived stages. A route-level test locks this
   in.

Out of scope (do NOT implement): a dedicated separate "Archived" view; PM
un-archive/restore; auditing PM archived-card views; any change to backend read
guards, the admin-archive route, card/file DELETE guards, or the CardDetailModal
canArchive/canDelete logic.
</objective>
