<objective>
Stop the auth rate limiter from blocking legitimate MFA enrollment and local dev/testing. The
onboarding sequence (login -> set password -> TOTP setup -> verify-setup, plus retries) trips
`authRateLimiter` (windowMs 60s, max 5) and returns 429 on `POST /api/auth/totp/setup`, surfacing
as "Failed to generate QR code". Give `authRateLimiter.max` a `NODE_ENV==='development'` override
(high in dev, 5/min in production) — an exact mirror of the existing `generalRateLimiter` pattern.
This automatically covers `loginRateLimiter` (alias) and every auth/MFA endpoint. Production
hardening is unchanged; tests stay exempt via the existing `skip: skipInTest`. No frontend change,
no dependency, no migration.
</objective>
