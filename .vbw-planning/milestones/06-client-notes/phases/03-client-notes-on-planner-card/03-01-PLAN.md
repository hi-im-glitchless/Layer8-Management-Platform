<objective>
Surface each client's notes, read-only, on the planner card detail modal, directly above the
existing project NotesEditor. Reach the data by widening the client select that boardService's
listCards/getCard already perform (the Client.notes column exists from Phase 01) — do NOT call
Phase 01's per-client endpoint. Render the notes through a single shared markdown path by
extracting an exported NotesPreview from NotesEditor.tsx, so exactly one SANITIZE_SCHEMA and one
render path remain. Guard the null-client and empty-notes cases so nothing (not even a heading)
renders. Leave the Kanban tile and the project NotesEditor untouched.

Resolved decisions (see <context> research for full rationale):
1. NotesPreview extraction — CONFIRMED. Add one named export
   `NotesPreview({ content, className? })` to `@/components/NotesEditor`. Keep SANITIZE_SCHEMA
   module-private (do NOT export it). NotesEditor's own Preview tab delegates to NotesPreview,
   passing the field-chrome className so its DOM stays byte-identical and the existing
   "sanitizes the preview" test passes unmodified. This is the export surface: exactly one new
   named export, no schema export.
2. Select const — extract a top-level `PROJECT_CLIENT_SELECT` const in boardService.ts and use
   it in both listCards and getCard, matching the sibling ASSIGNMENT_TEAM_MEMBER_SELECT
   precedent two lines above; prevents the two duplicated selects drifting apart.
3. Attribution line — OMITTED. The section is read-only; "last edited by" lives in the Phase 02
   editing tool. Success criteria do not mandate attribution here.
4. Heading text — plain "Client Notes" with NO client-name suffix. The client name is already
   shown in the Client+tags row a few sections above; a suffix would be redundant, and this
   mirrors the plain "Notes" heading on the card's own notes.
</objective>
