<objective>
Lift the board-only NotesEditor to frontend/src/components/NotesEditor.tsx (the flat shared location per the client-combobox.tsx precedent) and generalize its hardcoded useUpdateNotes() save into an onSave callback prop, so a non-board consumer (the Phase 2 client-notes modal, plan 02) can reuse the same editor and the same hardened rehype-sanitize schema. The board's existing card-notes save MUST keep working identically. Frontend-only; do NOT touch backend. This plan finishes the NotesEditor move so Phase 03 only adds a read-only section above it — no location/import churn in Phase 03.

Decisions resolved (rationale one-liners):
1. Prop contract (research open Q1) — Option 1: replace the internal useUpdateNotes() call with onSave(notes) => Promise<unknown> | void + isSaving: boolean; drop the cardId prop, add a generic resetKey?: string for the draft-reset dep. Rationale: mirrors ClientCombobox's callback-lift convention (component owns zero mutation knowledge, callers own their hook); mutateAsync + isPending reproduce the board's prior onSuccess-only preview flip exactly.
2. Filename case — frontend/src/components/NotesEditor.tsx (PascalCase, matching the component's current name). Rationale: preserve the component filename; client-combobox.tsx's kebab-case is the outlier, not the rule.
3. notesUpdatedBy stays a pre-resolved display name (or null) supplied by the caller — the component never resolves ids. Rationale: keeps id→name resolution a caller concern (board already does this; plan 02's modal will too).
</objective>
